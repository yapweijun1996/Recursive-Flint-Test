A MODEL-SPECIFIC DETAIL

Flint owns its thinking.

Recursive documents no reasoning switch or budget: Flint decides whether to reason each turn. Our Pi off trials still produced thinking content. The high/off experiment compared requested labels, not verified reasoning-on and reasoning-off conditions.

05 / METHOD & LIMITSEnough detail to check the claims

What “passed”
actually means.

  1. 01

    Start a fresh session

    Pi, OpenRouter, no persisted conversation. The expanded tests disable project context, skills, extensions and MCP.

  2. 02

    Check execution records

    A read must actually occur against the correct file, succeed, and produce the required answer.

  3. 03

    Run the returned code

    The harness applies replacements to isolated files and checks behavior in a separate Python process.

  4. 04

    Keep every scored attempt

    One attempt per repair or effort task; ten random reads per configuration. No automatic retries.

This is a small custom benchmark.

These are isolated seeded defects and short tasks. They are not SWE-bench results, production-repository repairs, or proof of general coding-agent reliability.

Timing includes more than inference.

Wall time includes CLI startup, network, generation and tool round trips. Three configurations may use different upstream infrastructure. Total time preserves slow requests; the median describes a typical observed call.

Reasoning budgets were not matched.

Luna received high or medium effort requests. Flint reasons autonomously. Sampling defaults, tokenization, caching and provider behavior can differ. A higher effort label does not establish an equivalent amount of work across models.

Corrections are recorded, not hidden.

An early scorer rejected valid absolute file paths; scoring now compares the resolved target file. A pilot had ambiguous interval-adjacency wording. That pilot was retained separately and excluded before the scored run. Expected behavior and tests were not relaxed.

Execution is intentionally bounded.

Only the read tool was exposed for repair and reading tasks. The harness applies code and runs trusted tests with AST/import restrictions, restricted builtins and a five-second verification timeout. This is not a general-purpose operating-system sandbox.
